Problem Statement — What We Are Solving

Uttarakhand receives over 35 million tourists every year for Char Dham Yatra, trekking, and religious tourism. But the traveler experience is broken in 4 critical ways:

Problem 1 — Fake Listings & Tourist Scams: Local agents put up fake homestay listings. Tourists pay advance for bookings that don't exist. Rental shops rent scooties with fake fitness certificates and expired hill permits on mountain roads.

Problem 2 — No Emergency SOS for Trekkers: Trekkers go missing on routes like Roopkund, Kedarkantha, and Valley of Flowers. Rescue teams get phone calls too late — without GPS coordinates or altitude data. In 2021, a Nainital landslide stranded 33 trekkers for 36 hours because no rescue team had their location.

Problem 3 — Local Economy Exploited: OTA platforms (OYO, Booking.com, Airbnb India) charge 20–30% commission from local Pahadi homestay owners. A family earning ₹1,000/night loses ₹250–300 to middlemen on every booking, draining the local mountain economy.

Problem 4 — Generic AI Fails in Mountains: ChatGPT doesn't know which passes are closed in January, acclimatization schedules for Kedarnath at 3,553m, or active landslide advisories. Tourists plan impractical itineraries and end up stranded.

Web3 Blockchain — Smart Contracts & Escrow

Core Problem: A MongoDB field isVerified: true can be changed by a hacked admin or compromised server. There is no way for a tourist to independently verify it without trusting the platform.

Our Solution: Anchor verification hashes on public EVM blockchain. No admin on our team can fake a verification without a valid cryptographic private key. Anyone with the QR code can verify independently.

Smart Contract 1: PartnerVerification.sol

Partner Submits Documents (fitness certificate, license, registration) │ ▼ Admin Reviews → Signs verification hash on-chain verificationHash = keccak256(listingData + salt) ← Private details stay off-chain │ ▼ attestListing(listingIdHash, verificationHash) called on EVM ✓ Version increments contract-controlled (cannot be faked or rolled back) ✓ Status: ACTIVE ✓ Event emitted: ListingAttested(hash, version, verifier, blockTimestamp) │ ▼ Tourist Scans QR Code → /verification-proof page isListingActive(listingIdHash, expectedHash) called (FREE view function, 0 gas) Returns: isActive = TRUE / FALSE, version = current version STATE MACHINE (immutable, cannot go backward): NONE ──► ACTIVE ──► SUSPENDED ──► ACTIVE (cleared investigation) └──► REVOKED (PERMANENT, sealed forever)

Smart Contract 2: VehicleRegistry.sol

RTO Inspector / Admin registers vehicle hill permit: permitDigest = keccak256(permitType + district + validUntil + salt) registerVehiclePermit(vehicleHash, permitDigest, expiresAt) Tourist scans scooty QR code → isPermitValid() called: isValid = status is VALID AND block.timestamp ≤ expiresAt AND hash matches isExpired = block.timestamp > expiresAt ← AUTOMATIC, zero gas, no write needed KEY INNOVATION: Permit expiry is checked inside an EVM view function. Expired permits are automatically invalid without any manual blockchain transaction!

Escrow Payment Flow

STEP 1: Tourist books homestay → pays ₹5,000 └── Payment LOCKED in Smart Contract Escrow vault └── Partner CANNOT withdraw yet STEP 2: Tourist arrives → scans QR code on homestay door └── isListingActive() returns TRUE ✔ STEP 3: Cryptographic check-in recorded on-chain └── Escrow triggers automatic release STEP 4: Funds released automatically: ├── ₹4,500 (90%) → Pahadi host's wallet / bank account └── ₹500 (10%) → Platform fee STEP 5 (if verification FAILS): └── Escrow releases 100% instant REFUND to tourist ← No fraud possible

Technology Justification & Recommendations

Why LangGraph (not a plain OpenAI API call)?

Travel planning is inherently multi-turn. A stateless LLM call forgets context between messages. LangGraph MemorySaver preserves entities (destination, budget, duration, preferences) across all conversation turns. If a user says "Plan Chopta" then asks "which of those stays has a kitchen?" — LangGraph retains Chopta context automatically.

Why Blockchain (not a database flag)?

A MongoDB isVerified: true field can be changed by any admin with DB access. An EVM smart contract hash requires a valid cryptographic private key to alter. Every state change emits a permanent on-chain event. Tourists can verify authenticity by scanning a QR code — no trust in the platform required.

Why Flutter (not React Native)?

CriteriaReact NativeFlutter
PerformanceJavaScript bridge adds overheadCompiled native Dart — faster on mid-range Android
UI ConsistencyPlatform widgets varyPixel-perfect on all Android/iOS devices
SOS + Camera + GPSMultiple native module configsSingle unified plugin per feature
Build APKExpo/bare flow complexityflutter build apk --release — one command

Why Razorpay + Stripe (not one payment gateway)?

Razorpay supports UPI, NetBanking, and IMPS — essential for Indian Pahadi users. Stripe covers international credit cards for foreign tourists visiting Uttarakhand. Using both maximizes payment coverage for all traveler types.

Why Upstash Redis Cache (TTL: 600s)?

Our destination database is read-heavy and rarely updated. Without caching, every request hits MongoDB adding 200–300ms. With Upstash Redis, cached responses serve in under 5ms — a 40–60x speed improvement for the most common API endpoints.

Hackathon Judge Q&A Defense

Why use Blockchain in a travel app? Isn't it just a buzzword?
In mountain tourism, fake vehicle permits and scam homestays are a real-world problem costing tourists lakhs during Char Dham Yatra. A central database can be altered by a corrupt admin. By attesting verification hashes on EVM smart contracts, we create a tamper-proof public record that anyone can verify with a QR code scan — no crypto wallet needed.
What does LangGraph do that plain ChatGPT doesn't?
LangGraph preserves stateful multi-turn session memory. When a traveler says "Plan Kedarnath trip" and then asks "which of those stays has hot water?", LangGraph retains Kedarnath context automatically. Plain ChatGPT forgets context between messages. Plus our AI is grounded with 105 Uttarakhand destinations, real weather data, landslide advisories, and altitude profiles — none of which ChatGPT knows.
What happens if internet drops during an SOS in a mountain valley?
We built Offline-First SOS Queuing. When the SOS button is pressed in a zero-network zone, the app captures GPS + Altitude + Battery and saves the payload to IndexedDB local storage with a UTC timestamp. A background service worker polls every 10 seconds. The moment 2G/3G/satellite signal is detected, it auto-dispatches the queued SOS to our Rescue Ops console.
Why did you build a Voice Bot? Why not just text?
Trekking on steep Himalayan trails or riding a scooty on winding mountain roads makes touchscreen typing dangerous and impractical. Our Devbhoomi Voice Companion enables 100% hands-free Hindi and English queries with sub-second audio response via Gemini Live WebSocket streaming. It's specifically designed for mountain use cases.
How does your Escrow protect tourists from scam hosts?
When a tourist books, payment is locked in a Smart Contract Escrow — the host cannot touch it. On arrival, the tourist scans the homestay QR code and the app verifies it against the blockchain. If it passes, 90% goes to the host. If it fails (fake or non-existent), the Escrow automatically triggers a 100% full refund. No fraud is possible without a valid cryptographic signature.
How does this help local Pahadi economy and not just tourists?
OTA platforms like OYO and Booking.com take 20–30% commission from local homestay owners every booking. Our Partner Hub lets local Pahadi families list directly, keep 90% of revenue, and get Web3 verified badges that build tourist trust — without any middleman. We built this platform to empower the mountain economy, not exploit it.
